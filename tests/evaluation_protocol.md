# 预先确定的评测方法

## 实验配置

八个公开案例，每组每案例重复三次，共 72 次调查。A 为直接 LLM，B 为 LLM 加工具，C 为 LLM 加相同工具及专业 Skill。三组使用 DeepSeek Flash、temperature=0、thinking=false 和相同结构化回答格式。相同案例和重复编号的 B/C 采用相同仿真种子策略。

全部原始配置、观测、业务目标和模型假设以相同提示发送给三组。B/C 可通过工具执行计算和仿真，C 额外加载 Skill。参考答案保存在评测文件中，运行期工具仅访问公开案例和本次仿真结果。

每次调查上限为 16 次模型请求、24 次功能工具调用、16384 个仿真帧。每次模型响应最多 3000 Token。结构化结果校验重试上限为 2。记录实际消耗与失败。

## 参考答案

每个已知信道案例、每种候选使用独立参考种子仿真 8192 帧。BLER 的 Wilson 双侧 95% 上界不超过业务上限、有效吞吐区间下界满足最低要求时，配置进入可行集合。可行集合中有效吞吐距最佳值 5% 以内的配置均接受。

全部配置均有违反约束的区间证据时，参考判断为 no_feasible_option。缺少信道或指标定义时为 insufficient_evidence。参考样本临界时也保留不确定结果。该标准适用于本工程明确的受控通信模型。

## 指标

1. 任务成功率为成功调查数除以全部计划调查数。成功需运行完成、decision 与参考一致、推荐配置在可接受集合中。C06 另需正确的 Es/N0 换算值，误差不超过 0.01 dB。C08 另需 pilot_sufficient=false，反映原始 0/8 计数的局限。
2. 平均运行时间为每次调查完整墙钟时间的算术平均，包含工具计算和 API 等待。另列平均 Token、请求数、仿真帧数。联网和并发会影响墙钟时间。
3. 有效证据引用率为实际存在的引用编号数除以全部引用编号数，重复编号去重，空引用计零。此指标检查来源可追溯性，证据与文字论断之间的语义对应关系通过代表性案例人工复核。
4. 功能工具成功率为正常返回且 status 非 error 的功能工具次数除以功能工具返回或参数重试次数。A 组记为不适用。结构化 final_result 输出调用从该指标中排除。

逐案例和逐次原始数据全部保存，汇总呈现组平均、案例成功数量以及三次重复的成功率波动。测试集规模为八个自建案例，泛化能力需扩大数据集进一步检验。
